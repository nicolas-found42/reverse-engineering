# Independent review of integer-division verifier

Read-only review of `tools/recomp/verify_integer_division.py`, `tools/recomp/integer_division_probe.cpp`, and `tools/test_recomp_integer_division.py` against the pinned PS2Recomp source and the supplied pinned PCSX2/manual evidence.

No actionable defect found in the bounded verifier. The source checkout commit and SHA-256 values for the runtime header, `SPECIAL_DIV`/`SPECIAL_DIVU` translator, and `MMI_DIV1`/`MMI_DIVU1` translator are checked before extraction; the SSE2NEON header is pinned too. `extract_case` substitutes `rt` before `rs` for each quotient/remainder template according to its corresponding `fmt::format` arguments. The generated wrappers include the production 32-bit low-lane extract helper and both GPR read macros.

The oracle avoids signed 32-bit `INT32_MIN / -1` UB by converting each signed word to a representable `int64_t` and dividing there. Converting the quotient or remainder to `uint32_t` preserves the low 32-bit result; `extend` then constructs the sign-extended 64-bit word. The unsigned path guards divisor zero before `/` or `%`. It models all divisor-zero results from the pinned source; Sony documents the arithmetic result as undefined, so these checks establish a pinned software profile only.

The probe sets nonzero sentinel data in register zero, uses valid sign-extended source words in low 64-bit lanes, and checks that all 32 register vectors stay unchanged. It verifies the selected HI/LO bank against the oracle and the other bank against its initial sentinels. The six modes test normal and reversed argument order, zero dividend, zero divisor, aliased source registers, and both zero registers. The separate negative control toggles the low quotient bit after each actual emitter and requires all four operations to detect every comparison as a mismatch. It checks quotient-path sensitivity, not every possible oracle or HI-write defect.

I ran `python3 -m unittest discover -s tools -p 'test_recomp_integer_division.py' -v`: eight focused tests passed in 2.522 seconds. The test set covers wrong commit, changed source, missing case, existing output preservation, missing checkout, dependency drift, extraction/HI-LO banks, and native matrix plus mutation control. Source, argument ordering, signed overflow, result sign extension, register and bank preservation, and negative-control structure were manually reviewed. No game code, emulator, or hardware ran; no shared source was edited.

Jev results are retained in the adjacent `independent-jev-*.json`. The code review escalated (`composite=0.86458`, `safe_to_apply=0.41`) due low-confidence blast-radius/test-gap rubrics despite high correctness/spec scores. Its escalation is preserved, not retried. The separate claim verification verified all four bounded claims, including signed-overflow avoidance, argument order/source macros, observed check counts, and the zero-divisor scope. These judgments are review evidence rather than proof of hardware behavior.
