# Texture descriptor identity and draw-side TEX1/MIPTBP1 path

This supplement establishes a bounded static pointer relationship from the texture descriptor loaded by the model loader to the descriptor pointer selected by the draw command path. It also records how two words in that same object are emitted as TEX1 and MIPTBP1 state. It does not establish that every descriptor is submitted or that any particular mip level is sampled by a draw.

## Result

`0011ecd0` returns a group context in the table based at `0x00233070`, with entries spaced by `0x114` bytes, and constructs a handle whose group slot occupies bits 23:20. `0021b6e0` extracts those same bits, multiplies the slot by `0x114`, and reconstructs the same group-context base.

The model-loader path passes that context to `0022ba30`. That helper allocates the group context's `+0xec` pointer table and stores aligned texture-descriptor pointers in indexed entries. It invokes `0022c660` on pointers loaded from that table. On the draw path, `0021d180` recovers the same group context and calls `0021bc18`; for a non-`0xffff` command index, `0021bc18` selects a pointer from the same `+0xec` table and writes it to the global consumed by `0021c3e0`. The latter conditionally calls `0021b850` with that pointer. Thus, when the command index is valid and the state path takes its non-null branch, the pointer used by `0021b850` is the same descriptor pointer that the loader placed in the group table and passed through `0022c660`.

In `0021b850`, the descriptor's `+0x18` and `+0x14` words are assembled as `(word_at_14 << 32) | word_at_18`. The pinned PS2Recomp `PCPYLD(rs,rt)` implementation uses `_mm_unpacklo_epi64(rt,rs)`, so the low 64-bit lane contains this assembled value and the high lane contains selector `0x14`. The emitted selector is `0x14` (`TEX1_1`). The same function emits the descriptor's `+0x20` value with selector `0x34` (`MIPTBP1_1`).

`0022c660` stores the signed halfword at descriptor `+0x08`, sign-extended, at `+0x14`; it stores a packed value at `+0x18` containing `mip_count << 2`, a signed halfword from `+0x0a` shifted into bits 20:19, and the MMAG/MMIN terms. Accordingly, the emitted TEX1 has LCM bit 0 clear, MXL equal to the serialized mip count, and K sourced from the signed halfword at `+0x08`; the L field is sourced from the signed halfword at `+0x0a`. `0021b850` also reads descriptor `+0x38` and bytes `+0x36/+0x37`, but these form a separate selector `0x47` (`TEST_1`) packet, not TEX1.LCM.

## Bounded corpus observation

A separate deterministic recount of all 56 archive-bound model files selected rows with format 3 or 4, descriptor flag bit 8 set, logical level size 8×8, and record DBW/TBW values both equal to 2. It found 75 rows: 15 with serialized mip count 1 and 60 with count 2. The raw descriptor selector bits 10:9 split 56 rows with value 0 and 19 with value 1; source flag bit 5 is set on all 75. Those selector bits are reported as raw values only. With LCM clear and MXL 1 or 2, these descriptors configure the available mip-level ceiling, but this does not prove an individual draw selects those levels from per-vertex Q and L/K.

The selector bytes at descriptor `+0x36/+0x37` feed TEST_1, not TEX1. The pinned header defines TEST fields as ATE bit 0, ATST bits 3:1, AREF bits 11:4, AFAIL bits 13:12, DATE bit 14, DATM bit 15, ZTE bit 16 and ZTST bits 18:17. For raw selector value 1, `0022c660` stores bytes 5 and `0x40`, which `0021b850` emits as ATST=5 (GEQUAL) and AREF=`0x40`. For selector value 2 it stores 6 and zero, giving ATST=6 (GREATER) and AREF=0. The emitted TEST word also takes ATE from descriptor `+0x38` bit 0, sets ZTE, and selects ZTST 1 or 2 from a global-dependent value. Jev verified these exact encoded fields in a separate bounded check.

The available instruction capture does not establish the per-vertex Q source for the `0021d180` command path. It shows `0021d180` selecting descriptor state and `0021b850` emitting GS setup. A separate function, `00228b38`, is itself a direct caller of `0021b850`; it then packs 12 words per vertex, may call VU microprogram `0x268` for two output words, and submits the buffer through `00228908`. This is a separate candidate textured draw path, but the capture does not identify those two output words as GS Q or map the VU input/output layout. Keep the per-draw LOD choice unresolved.

The earlier `mip-draw-state-path-raw-01.json` record remains preserved as historical and said object identity was unproved. Earlier Jev results that assigned descriptor selector bits to TEX1.LCM or treated all address-intersection rows as actually sampled are also retained as superseded. The corrected raw trace shows selector `0x47` is TEST_1, while the complete TEX1 `+0x18` expression has no bit-zero term. No draw-by-draw LOD selection was evaluated.
