# Independent static recovery experiments

This snapshot continues the static recovery saved in commit `a6998de`. The game is still incompletely recovered. These results add an independently generated C++ artifact, a comment-integrity checker, native compilation evidence, and bounded IOP context experiments. Whole-game generated source, assembly, executable bytes, native objects, and archives remain in ignored local scratch.

The command-line PS2Recomp generator at GitHub commit `c5a9d02573410a2085a4b4b831b0b68ba3515440` built on macOS ARM64. `native-tool-provenance.json` pins the executable and six fetched dependency commits. The generator used the exact PAL executable SHA-256 `216711210898aee296eed73d0776e7f733bac04c334002683bce769c86beea95`, no function map, no configured stubs or skips, and disabled instruction patching. Its report records 4,746 generated functions, zero decode failures and unhandled instructions, and 1,178 unresolved control-flow warnings. Its 88,104 resumable entry points and 145,340 fallback-entry promotions are tool heuristics, not recovered original functions.

`artifact-verifier.json` records the independently checked instruction comments and function-start comparison. All 302,334 unique commented instruction words match file-backed EE executable sections and their ELF LOAD mappings. Compared with the 3,837-function Ghidra inventory, the generator supplies 1,113 additional starts: 969 unowned addresses and 144 addresses inside existing instruction bodies. Conversely, 204 Ghidra starts are absent from the generator. There are 71,482 comment addresses outside that saved instruction inventory and 4,573 saved instruction addresses absent from the comments. These differences identify research candidates; comment presence neither validates translated operations nor establishes the original function boundaries.

All 4,746 function files plus the registration file passed C++ syntax checking. They also compiled into ARM64 object files and an 83,505,440-byte static archive. The first registration-object attempt timed out at 60 seconds; the second completed successfully in 86.85 seconds. Both attempts are retained. The original object manifest accidentally omitted the `-o` argument from its recorded command arrays; `object-command-correction.json` records the actual invocation arguments without replacing that original manifest. This is compilation evidence only. The archive has not been linked to a complete runtime or executed as a game, and hardware support and behavioral equivalence remain unverified.

The new `tools/verify_recompilation.py` checker supports the generator's fallback `sub_...` artifact profile. It validates each function artifact's filename, aligned range, source hash, entry comment, instruction words, executable-section bounds and LOAD mapping, and compares report counters with the actual files. It first validates the saved comparison inventory's bytes. Its result always preserves `whole_game_decompiled: false`. The checker intentionally does not certify the C++ body: an empty-body test fixture with genuine comments can pass the narrow comment check while still making no semantics claim.

Independent review reproduced a forged-comment path through C++ raw strings in the shared comment scanner. The scanner now skips raw literal payloads using their exact delimiters, and regressions cover standard prefixes, embedded quotes, forged comments, and unterminated literals. The artifact checker has 15 negative-control and scope tests; the Ghidra export verifier's 14 tests also passed. The complete Python suite passed 183 tests using the existing TypeSafe SDK environment; type checking passed with zero errors and warnings. Logs are retained beside this document.

Synthetic tests against PS2Recomp's pristine runtime macros found undefined signed C++ overflow in `ADD32_OV` and `SUB32_OV`: `INT32_MAX + 1` and `INT32_MIN - 1` trigger UBSan before overflow handling. Ordinary addition/subtraction controls pass. `overflow-baseline.json` retains the outputs and probe hash. No game function, game state, runtime, or emulator was executed in those tests. Actual gameplay reachability of either overflow state is unknown. The separately pinned `tools/recomp/defined-overflow.patch` correction uses 64-bit intermediates and explicit signed 32-bit bounds. It passes 594 result/overflow comparisons across 297 input pairs under UBSan. A faulty intermediate predicate and its failure are retained, together with both model gates. The final gate's arithmetic claims were verified while its review remained escalated on integration confidence. Root subsequently compiled all 4,746 generated functions against the complete corrected runtime header and archived them with the registration object; `overflow/archive-integration.json` records 4,746 defined function symbols and the 83,514,888-byte archive. The baseline archive remains separately retained with the original header. Neither archive has been linked or run as a game.

The no-return audit found only one flagged Ghidra function, `00105888`. Its terminal flow calls the returning helper `00105ac8` and then spins at `00105aa8`; no `jr ra` occurs in its saved body. All 463 relevant C warning comments name that function; the raw inventory has 435 direct calls and 28 unconditional tail transfers to it. The bounded aggregate result is retained in `no-return-summary.json`. No no-return flag was changed.

`iop-gp-context.json` records a separate source-pinned Loadcore comparison. The module GP field is the third `.iopmod` word; a runtime base is dynamically allocated and cannot be recovered from the static file alone. A base-zero Ghidra context correction matched all 24 exact inputs without changing any memory-block bytes or imported text hashes. All 2,241 function entries remained identical, all C exports succeeded, and warnings stayed at 91. Three C artifact hashes changed without signature changes. There are no GP-based load/store instructions in executable text in this corpus. Three opcode-shaped words in LIBSD data were excluded as noninstructions.

The private relocation model processed 24,783 rows at base zero and synthetic base `0x00100000`; base zero was an identity control and the synthetic base changed all 24 modules. It is a comparative experiment against PS2SDK Loadcore commit `89b9d8cf249f927192c57804ce5e55e99e34002d`, whose version has not been matched to the game's loader. Its out-of-range section-loop read and the model's deliberate in-range-only handling remain documented. Runtime placement, import resolution, cache behavior, and equivalence to the target loader are unproved.

Firecrawl fetched the exact pinned [PS2Recomp README](https://raw.githubusercontent.com/ran-j/PS2Recomp/c5a9d02573410a2085a4b4b831b0b68ba3515440/README.md) and the [LLVM UBSan reference](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html). Jev screened these primary sources, checked bounded results and deliberate overclaims, and reviewed the artifact checker and raw-string fix. Full model results are preserved under `jev/`; default thresholds were retained. Several patch reviews escalated on confidence rather than supplying a concrete defect, and those outcomes remain escalated. The independently reproduced lexer defect was fixed and retested. A positive bounded compilation claim was marked review, and claims that compilation proves equivalent behavior were contradicted. Some early screen receipts retain input/result but omit the complete purpose argument; their tool invocations remain in the chat history. No failed or low-confidence result is presented as model approval.

The next recovery work is to prove useful additional function entries, resolve bounded switch-table and character-table dispatches, finish the helper correction, and establish VU arithmetic contracts. The original saved inventory still leaves 305,628 physical executable bytes unclassified; the larger generator coverage does not close that discovery or semantics gap. Original names, types, build reproduction, IOP loader matching, hardware behavior, and whole-game equivalence remain open.
