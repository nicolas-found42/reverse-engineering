# Runtime and generated-object link result

The bundled CMake 3.31.6 and Unix Makefiles built and linked the actual pinned PS2Recomp runtime with the 16 generated function batches and generated registration object. The final output is an arm64 Mach-O executable, 81,438,416 bytes, SHA-256 `ecfa7280d4be2be36467cce068f1927c001c15732f57d0cb4932bbd6fb3870e2`. The final link has 4,746 distinct guest entry addresses and exactly one strong definition each of the four `g_ps2RecompiledFunctionTable*` globals.

The link-check wrapper removes the runtime's zero-initialized `ps2xRuntime/src/runner/register_functions.cpp` source, which otherwise duplicates the four table globals in the generated registration object. The first attempt without that filter failed on those duplicate symbols; the successful second attempt retained the generated registration object. Both outcomes remain in separate immutable build-02 evidence. The earlier symbol-count parser error is also preserved and superseded by this direct count from C++ mangled symbol names.

The private PS2Recomp source clone is based on `c5a9d02573410a2085a4b4b831b0b68ba3515440` with experiment modifications recorded in the result metadata. Raylib is source-pinned to tag 5.5 / commit `c1ab645ca298a2801097931d1079b10ff7eb9df8`, with its license identity recorded. The wrapper points FetchContent at the six existing generator dependency trees. Because recompilation is disabled, only the arm64 configuration consumed `sse2neon`; the other five generator dependencies (ELFIO, fmt, libdwarf, rabbitizer, and toml11) were not fetched or built for this runtime-only target. FFmpeg, debug UI, unity, PCH, and sccache are disabled. Raylib and the runtime IOP library still compiled and linked as desktop backend dependencies.

This is a compiler/linker result, **not a verified headless execution**. The produced artifact is the normal runtime runner and includes the real raylib/IOP host backend. It was never launched. No claim is made about boot, gameplay, media decoding, graphics output, or whole-program behavioral equivalence. Runtime TODOs and fallbacks remain.

The first CMake attempt asked for Ninja, but the binary was absent; the final attempt used Unix Makefiles. The complete successful build command, actual final link command inputs, hashes, source filters, source pins and compiler warnings are captured in `result.json`. Generated code bodies are excluded from permanent evidence; only hashes, counts, paths, and tool output metadata are retained.
