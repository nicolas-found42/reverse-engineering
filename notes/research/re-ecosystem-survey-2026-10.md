Research date: 2026-10-08. Scope: public GitHub repos and release/changelog pages, official tool docs, the MCP spec and registry, and arXiv (2026-07 → 2026-10). This note **adds to** [ps2-tooling-and-techniques-survey-2026-10.md](ps2-tooling-and-techniques-survey-2026-10.md) (2026-10-05), [ps2-github-decompilation-practices.md](ps2-github-decompilation-practices.md) (2026-10-04), and [dev-tooling-survey-2026-10.md](dev-tooling-survey-2026-10.md) (2026-10-08, uv/Ruff/ty/pytest) and does not repeat them. ## A. MCP servers for reverse engineering (first dedicated survey in this repo)

The prior survey named only GhidraMCP and ReVa in single lines. The 2026 state: **MCP support has become first-party** — Hex-Rays, Vector 35, radareorg, and LLVM/LLDB now ship their own servers — while the once-dominant community Ghidra bridge is stale and carries documented security findings.

Ecosystem baseline: MCP uses date-versioned revisions; current revision **2026-07-28** (prior 2025-11-25, 2025-06-18) ([versioning](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning)). The official **MCP Registry** previewed 2025-09-08 with API freeze v0.1 on 2025-10-24; publishing is namespace-verified via GitHub OIDC or DNS/HTTP challenge ([registry](https://github.com/modelcontextprotocol/registry)). Discovery lists: `punkpeye/awesome-mcp-servers`, `appcypher/awesome-mcp-servers`, RE-specific `crowdere/Awesome-RE-MCP`.

Maturity labels: `jev_classify` over 15 servers with a first_party / active_community / stale / manual_review catalog — **15/15 `auto`** (4 first-party, 8 active, 3 stale). Stale set: GhidraMCP (LaurieWired), frida-mcp (dnakov), PCSX2-MCP.

Security synthesis (all from the owning servers/issues): (1) unauthenticated HTTP is the dominant default — GhidraMCP binds `0.0.0.0` with no auth; Binary Ninja and r2mcp instead ship optional bearer tokens, and r2mcp defaults to localhost. (2) Prompt injection is inherent when the input is hostile binary content (GhidraMCP #140 calls it a "near-certain attack surface"), and comment write-back makes it persistent. (3) Decompiled content flows to the configured LLM provider; Hex-Rays positions its server as fully local for air-gapped/NDA use. (4) Scripting-escape servers (IDAPython execute) can reach beyond the analyzed database — vendor-recommended sandboxing. (5) Third-party scanner grades (MCPSafe, AgentSeal) exist but the underlying issues are the primary evidence.

**PS2/R5900 relevance.** None of the surveyed servers carries PS2/R5900 knowledge — they are host-tool bridges; R5900 semantics still come from the repo's own Ghidra extension. For this project the interesting pieces are: headless Ghidra MCP for batch analysis (bethington/ghidra-mcp, ReVa), and PCSX2-MCP as the only existing dynamic-oracle bridge — which would need owner approval before any use against the corpus ([ADR-0002](../../docs/adr/0002-headless-execution-permitted.md) permits headless execution; it does not authorize connecting tools to the game). No PS2-specific MCP server exists (absence across GitHub search and the RE-MCP lists; not proof).

What PS2 projects actually use (each citing its own docs/source): **`dvp-as` from `ps2dev/binutils-gdb` branch `dvp-v2.45.1`** (`INSN_5900`, `CPU_R5900`, `MMI`/`VU0` opcode tables — the exact branch ADR-0003 already pins) for VU and EE assembly; `ps2toolchain-{ee,iop,dvp}` build binutils 2.45.1 + gcc 15.2.0 (modern gcc is *not* the matching compiler). R5900-capable newcomers and specialists:

- **[rabbitizer](https://github.com/Decompollaborate/rabbitizer) 1.16.2** (2026-05-29, MIT) — per-word MIPS decoder with **explicit "R5900 (PS2's Emotion Engine processor) decoding support"**, references ps2tek/C790/VU manuals, "should produce matching assembly"; limitation: decodes one word at a time, no multi-word pseudo-instructions. Strongest drop-in EE decode library for a matching pipeline.
- **[spimdisasm](https://github.com/Decompollaborate/spimdisasm)** (MIT) — matching MIPS disassembler listing "PS2's R5900 EE instruction set support"; the backend `splat` calls for PS2. Its own caveat: generated assembly is "not guaranteed to match or even be assemblable".
- **[chaoticgd/ccc](https://github.com/chaoticgd/ccc)** (MIT) — `stdump` for `.mdebug`/STABS (+SNDLL in 2.x; DWARF "in the works"); the maintained library behind the EE:Reloaded STABS analyzer; relevant to this repo's `ecoff_mdebug.py`.
- **[reko](https://github.com/uxmal/reko) 0.12.5** (2026-09-29, GPL-2.0) — "Added support for PS2 Emotion Engine — disassembling and lifting PS2 EE binaries … EE calling convention"; author notes it is "not a complete implementation yet".
- **[naken_asm](https://www.mikekohn.net/micro/naken_asm.php)** (GPL-3.0) — the only non-binutils assembler with **stable Emotion Engine and EE-VU** asm/disasm; no byte-exactness claim vs `ee-gcc`/binutils output was found → cross-check tool, not the matching assembler.
- `[LEAD]` **LLVM PR #176666** adds `-mcpu=r5900` (sets `EF_MIPS_MACH_5900`); "Future work" lists **MMI** and **COP2/VU0 macro mode** as not yet implemented — merge status unverified ([thread](https://lists.llvm.org/pipermail/cfe-commits/Week-of-Mon-20260112/797486.html)).
- `[LEAD]` **Binary Ninja 5.1 "Helion"** integrated the R5900 arch "on all paid editions … and is open source" ([post](https://binary.ninja/2025/07/24/5.1-helion.html)); commercial host, so reference-only under ADR-0003.
- `[LEAD]` **decompals/binutils-mips-ps2-decompals** — GPL-2.0 binutils 2.40/2.41 branches with DVP relocation support (README not retrieved).

**pyelftools vs hand-rolled parsing.** The leading MIPS decomp toolchain does *not* depend on pyelftools — `splat`'s `mips` extra is `spimdisasm + rabbitizer + pygfxd + n64img + crunch64`. pyelftools is genuinely useful at the table level (MIPS reloc layouts, `SHT_MIPS_*`, `R_MIPS_*` names) but has no `EF_MIPS_MACH`, no `.mdebug`, and models none of this repo's section-payload semantics (`.reginfo` GP value, `.DVP.ovlytab`). It is public-domain (ADR-0003-safe) but non-stdlib: under `dependencies = []` it can only run out-of-band (e.g. `uvx`), never imported by `tools/`. The audited bounded parser stays the gate-side reader.

## E. How decomp/RE research repos are organized and kept neat (2026-10)

Conventions stack in seven layers; the strong repos (sm64, zeldaret/oot+mm, pret/pokered+pokeemerald, open-goal/jak-project, so3-decomp, dds-decomp, rac-deadlocked-decomp, nathanialf/ico, dtk-template, splat, tenchu, CrashBandicootXS) fill all seven. Selected patterns, each citing its exhibit:

1. **Layout**: one C file per start address until the real translation unit is proven (rac-deadlocked `src/core/<ADDR>.c`; dds-decomp keeps real TUs because a Nocturne debug build proves names); an explicit unbuilt `nonmatching/` (or `#ifdef NON_MATCHING`) draft area; a frozen `expected/` tree for carved targets (CrashBandicootXS).
2. **Symbol/provenance config**: `config/<version>/` holds splat YAML + `symbol_addrs.txt` + `reloc_addrs.txt` (+ `cflags.txt`, `not_functions.txt`, `name_sources.txt` side tables) — dds-decomp, so3-decomp, rac-deadlocked. **Name provenance is tracked, not assumed**: `name_sources.txt` marks evidence vs inferred; rac-deadlocked's LEGAL.md requires `git log -S<name>` before every push.
3. **Build**: pinned era compiler in a container; the build's **last step is the byte/hash gate** (oot 16-version CI matrix; dds ninja "fails unless every ELF is byte-identical"; ico `check_elf.py --gate --require-elf-sha`; pret `compare: $(SHA1) -c roms.sha1`).
4. **CI**: format gate, IP/legal gate as first-class jobs, cheap static checks before touching retail inputs; untrusted-input handling via private side channels (deploy keys) and allowlist + "ok to test" comment triggers (jak-project).
5. **Progress**: the **decomp.dev contract is artifact-based** — CI uploads an artifact named `<version>_report` containing an objdiff Report v2 JSON; the bot pulls it; there is no push API. Build-free report generators make this work for redistribution-constrained repos (tenchu `tools/objdiff-report.py`; rac-deadlocked commits `progress/report.json`, CI validates it and uploads the artifact). Receipt-backed credit is the rigorous end: dds-decomp's published progress pays game-function credit **only with compile/link receipts**, an all-assembly build earns zero C credit, and report generation fails on stale evidence.
6. **Docs**: style guide, reviewing checklist, onboarding tutorial, per-directory indexes (ico ships a one-line-per-tool `tools/README.md` and a `docs/README.md`); legal pages that separate *content* from *facts about its shape* and demand disclosure of leaked-material exposure on a first PR (ico, zeldaret/mm); ADRs remain **rare in decomp repos** — no surveyed peer has them; `AGENTS.md` for AI contributors is new (open-goal: "(AI-assisted)" disclosure markers, no agent-created issues/PRs).
7. **Hooks/triage**: ico auto-installs pre-commit (IP check → format → byte gate → regenerate progress docs) **plus a pre-push backstop** that re-runs the gate against the pushed ref, explicitly "the backstop for commits made with `--no-verify`"; ico's `check_dev_native.py` and dds's `check_unit.py` **refuse codegen-steering constructs** (K&R definitions, register pins, computed gotos) with allowlist lines that must carry ROM evidence. pret/zeldaret are Discord-first with no label vocabulary; this repo's GitHub-issues-as-tracker + five triage labels has no peer equivalent.

**This repo vs the field.** Ahead of every surveyed peer: ADRs with falsifiers and reproducing commands; the anti-term glossary; evidence bundles naming the reproducing command for every measured number; the non-steerable-gate rule; IP rails as a checked CI job; the triage vocabulary; `AGENTS.md`. Behind the field (peers' files listed in the survey notes): **no build/byte gate in CI** (ledger tools run manually with committed receipts), **no machine-readable progress artifact** (no objdiff-shaped `report.json`, no dashboard), no `config/` tables a build could read (flag/range decisions live inside prose evidence), no `tools/README.md`/`docs/README.md` indexes for the 200+ module tool corpus, no CONTRIBUTING/STYLE/REVIEWING equivalents, no `.recomp.json`, hooks are opt-in with no pre-push backstop, and no PR/issue templates or CODEOWNERS.

**Candidate adoptions, ranked by value over cost, constrained to a notes+tools-only repo** (no tracked game source, no redistributable compiler — explicitly *not* recommended: a per-function `src/<ADDR>.c` tree, a splat config, or any decomp.dev-style number whose denominator is not the [ADR-0005](../../docs/adr/0005-game-owned-sdk-boundary.md) game-owned split):

1. `tools/README.md` + `docs/README.md` one-line-per-file indexes (ico's shape).
2. A generated evidence index: walk `notes/evidence/*/README.md`, extract reproduce-command + corpus/commit pins, emit `notes/evidence/INDEX.md` + `index.json`.
3. `.recomp.json` under the recomp.fyi schema v1 — every field is already known (system ps2, type decomp, serial SLES-517.05, toolchain, links); it is the only cross-project discovery channel for PS2 decomps (board: 1,690 rows, `[LEAD: fetch failed, TLS]`).
4. A progress artifact in **objdiff Report v2 shape with `progress_categories`** (game-owned / mixed / substitute / unresolved), generated from the ledger tools and uploaded as `SLES_517.05_report` per the decomp.dev contract — externally visible without weakening "nothing approximately matched is counted", provided ADR-0005 gates the denominators.
5. A `config/` of machine-readable decision tables the tools read (`sections.tsv`, `units.tsv`, `flags.tsv` with the probe that justified each row, `not_functions.txt`) — generalizing the dds `key, value, evidence-comment` convention.
6. A documented `reconstruction/` + drafts convention (what may live there, what counts, where a near miss goes).
7. A `CONTRIBUTING.md` from the peers' recurring sections (prerequisites, own-copy warning, corpus hash, how to finish a unit, what makes a match, provenance disclosure on first PR).
8. `docs/STYLE.md` consolidating the note skeleton (status / established / not established / reproduce) and glossary terms.
9. `tools/install_hooks.sh` adding the pre-push backstop (closes the "hook is inert until configured" gap `docs/LEGAL.md` calls out).
10. A confirmed-shapes file (`docs/idioms.md` analogue): recovered prologue/epilogue, small-data access, MMI/COP2, VIF→VU handoff shapes, each with corpus address and measuring tool.
11. PR/issue templates + CODEOWNERS over `docs/adr/`, `tools/`, `notes/evidence/`.
12. A docs-hygiene + ledger-gate CI job (markdown link check; run `matching_ranges.py`/`ip_rails.py --tree` so a docs-only PR cannot silently invalidate a committed number).
